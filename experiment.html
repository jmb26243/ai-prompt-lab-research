EXPLORING PROGRAMMING PATTERNS

Experiment & Evaluation

Comparing two approaches to building flexible evaluation logic for AI prompt experiments.

OUR EXPERIMENTAL QUESTION

Does the Strategy design pattern make evaluation logic easier to extend and maintain?

We will compare a straightforward evaluation function with an implementation that uses separate evaluation strategies. Both approaches will perform the same basic task.

THE PROBLEM

Why investigate this?

AI Prompt Lab needs a way to evaluate saved prompt experiments. As the application grows, we may want to evaluate responses using different criteria.

01

A simple starting point

A single function can calculate an evaluation score using a fixed set of criteria. This is straightforward and may be sufficient for a small application.

02

A need for flexibility

If we introduce additional evaluation methods, the original function may become more complicated. We want to investigate whether separating evaluation strategies helps.

TWO IMPLEMENTATION APPROACHES

Simple function vs. Strategy pattern

Both approaches will use the same evaluation criteria and sample inputs so their structure can be compared.

APPROACH A

Simple evaluation function

Use one function to calculate an evaluation score from the supplied criteria.

CONCEPTUAL PYTHON EXAMPLE 
def evaluate_response(
    clarity,
    relevance,
    accuracy
):
    return (
        clarity +
        relevance +
        accuracy
    ) / 3

Potential advantages

  • Easy to understand and implement.
  • Less code and fewer components.
  • Appropriate for a limited number of rules.

Potential limitations

  • Additional evaluation methods may require changes to the function.
  • More complex rules could make the function harder to maintain.
APPROACH B

Strategy design pattern

Create separate evaluation strategies that share a common interface. Each strategy provides its own evaluation behavior.

CONCEPTUAL PYTHON EXAMPLE 
class EvaluationStrategy:
    def evaluate(self, response):
        raise NotImplementedError


class AverageStrategy(EvaluationStrategy):
    def evaluate(self, response):
        return sum(response) / len(response)


class WeightedStrategy(EvaluationStrategy):
    def evaluate(self, response):
        weights = [0.5, 0.3, 0.2]
        return sum(
            score * weight
            for score, weight in zip(response, weights)
        )

Potential advantages

  • Evaluation methods can be separated.
  • New strategies can be added independently.
  • May improve flexibility as requirements grow.

Potential limitations

  • Requires more classes and structure.
  • May be unnecessary for a very small application.

These are illustrative examples of the two approaches, not results from a completed implementation.

EVALUATION CRITERIA

How will we compare them?

We will use the same basic evaluation task and examine the differences between the implementations.

Criteria Simple function Strategy pattern
Initial complexity Expected to be lower Expected to be higher
Adding a new evaluation method May require modifying existing logic Can be added as another strategy
Code organization Centralized in one function Separated into strategy classes
Maintainability May become harder as rules grow May be easier with multiple methods
Best fit Small, straightforward requirements Multiple or changing evaluation methods

These are initial expectations based on the proposed designs. The experiment will determine whether they hold true in our implementation.

OUR PREDICTION

What do we expect to discover?

We expect the simple function to be easier to build initially, while the Strategy pattern may make it easier to introduce additional evaluation methods. However, the added structure may not provide enough benefit for a small project.

The goal is not to prove that design patterns are always better. It is to understand when their additional structure is worthwhile.

TESTING THE IDEA

Our experiment plan

We will follow the same steps for both approaches to make the comparison meaningful.

01

Build both implementations

Create a simple evaluation function and a separate Strategy pattern implementation.

02

Use identical sample data

Evaluate the same sample responses using the same criteria and expected results.

03

Introduce another evaluation method

Add a new evaluation rule and observe how much each implementation needs to change.

04

Run automated tests

Use Pytest to verify expected scores, input handling, and consistent behavior.

05

Compare and document the results

Record code complexity, changes required, test results, and what we learned.
